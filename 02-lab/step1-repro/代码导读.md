> 目标：让你能在 20 分钟内说出"从点按钮到屏幕出字，中间经过了什么"。
> 所有行号对应 `01-readings\scopeai\` 里的原始文件。

## 一、先看全景

```
                 ①采集                      ②提特征                 ③分类                 ④解释                ⑤显示
┌──────────────┐   ┌──────────────────┐   ┌──────────────┐   ┌───────────────┐   ┌─────────────┐

│ 电压序列      │──▶│ freq / amp /     │──▶│ 一份 .pkl     │──▶│ GPT-4o 生成   │──▶│ 波形+指标+   │
```

关键认知：**模型从头到尾没见过波形。** 它见的是一条 5 个数的向量，出来的是 13 个概率。
波形只用于画图和提特征，之后就扔了。

## 二、五个环节，逐个拆

### ① 采集 `capture.py`

**一个类管到底**，文件末尾 248 行 `_BACKEND = _ScopeCaptureBackend()` —— 这一行在 `import capture` 的时候就执行了，所以"用真机还是仿真"在程序启动那一刻就定了，运行中拔插 USB 不会切回来。

构造时（33–58 行）先看环境变量 `SCOPEAI_SIMULATE`；没设就去加载 `libdwf`（Digilent 的驱动 DLL），失败就 `_enable_simulation()`。**这就是"没有硬件也能跑"的实现方式：一张 try/except。**

输出：`(samples, sample_rate)`，samples 是 float64 一维数组，单位伏特，长度 = 时长 × 10000。

两个分支：

- 真机 `_capture_hardware`（123–165 行）：配量程 ±5 V、采样率 10 kHz、RECORD 模式，然后轮询状态、按块读 double。这 40 行是纯 ctypes 样板，看不懂不影响理解主线。
- 仿真 `_simulate_waveform`（173–196 行）：**整个"物理世界"就这 24 行**。

```python
# 173–196 行，简化后
wave = np.where(np.mod(t * freq, 1.0) < 0.6, 1.0, 0.0)   # 占空比 60% 的方波
volts = 0.1 + 1.8 * wave + np.random.normal(0, 0.01, n)  # 加 10 mV 噪声
```

六个故障只是改了 `freq`（2.5 / 0.5 / 7.0）和占空比（0.6 / 0.55 / 0.95）；`cap_missing`、`no_oscillation` 是常数 + 噪声，`chatter` 是纯噪声。**没有电感、没有 RC、没有任何电路方程**——所谓"仿真"是"照着期望的样子画波形"，不是电路仿真。

### ② 提特征 `features.py`

纯函数，输入波形和采样率，输出 5 个数的字典（29–102 行）。逐个看：

| 特征 | 公式 | 物理含义 | 坑 |
|---|---|---|---|
| `freq_hz` | 去均值 → rfft → 除直流外最大峰的频率 | 基频 | 噪声时最大峰是随机的，得到的是"某个高频" |
| `amplitude_rel` | `clip(ptp/2, 0, 1)` | 半摆幅 | 摆幅 > 2 V 就饱和成 1.0 |
| `jitter_ms` | 找峰 → 相邻峰间隔取标准差 | 周期抖动 | 找不到两个峰就是 0 |
| `spectral_spread` | `sqrt(ΣP(f−f0)²/ΣP)` | 围绕基频的谱宽（Hz） | 单位是 Hz，随采样率和噪声一起变 |
| `zero_crossing_rate` | 过零次数 ÷ 时长 | 每秒过零次数 | **没有幅度归一化**，底噪下恒为 fs/2 |

第 71 行的 `amplitude_rel` 和第 93 行的过零率，就是这一步的两个主要失效点——你已经复现过了。

### ③ 分类

没有单独的 model.py，逻辑散在 `app.py` 81–98 行和 `diagnose.py` 142–160 行，两处几乎一样：

```python
vec = np.array([feat[f] for f in FEATURES]).reshape(1, -1)   # 1×5
pred_enc = clf.predict(vec)[0]                               # 1 个整数 0..12
pred_label = le.inverse_transform([pred_enc])[0]             # "mode_A__nominal"
mode, fault = pred_label.split("__", 1)
confidence = clf.predict_proba(vec)[0].max()
```

三件要记住的事：

1. **标签是复合的**：13 类 = `模式__故障`。所以"电容缺失"在 A 和 B 里算两个不同的类。
2. **模式不是界面选的，是模型猜的**。`app.py` 285 行那个下拉框只有一个选项，纯装饰；真正决定模式的是 `pred_label` 的前半段。
3. **置信度 = 13 个概率里最大的那个**，不是"模型有多确定它对"。所以它可以在 70% 上确信地错。

### ④ 解释 `diagnose.py`

`auto_diagnose`（163–203 行）：**没有把波形给 GPT，只给了 4 个数**——故障名、置信度、频率、幅度。

```
"NE555P astable oscillator diagnosis:
ML Fault: mode_C__nominal (70% confidence)
Frequency: 7.00 Hz
Amplitude: 0.9367 ..."
```

外加一段写死的 system prompt（20–34 行），里面直接把"nominal 是 1–2.5 Hz""R_too_high 是 0.5 Hz"这些判据写成了自然语言。

结果是 164–166 行：`cache[(mode, fault)]`。**同一个故障类只调一次 API**，之后一直复用——所以改参数重测时文字不会变。

`chat`（265–352 行）是另一条路：给了模型两个工具（重新采集、查设备状态），最多循环 5 轮，每轮间隔至少 2 秒（54 行）防限流。

### ⑤ 显示 `app.py`

`main()`（271–343 行）每轮都从头跑一遍——Streamlit 的执行模型就是"脚本重跑"，状态靠 `st.session_state` 存。

一次点击 `Capture Now` 的完整路径：

```
main()                                     app.py 271
 └─ should_capture = True                  app.py 317
 └─ _run_sample_cycle(mode, interval)      app.py 133
     ├─ capture.capture(3.0)               → 30000 点（滑块默认 3 秒！）
     ├─ extract_features(samples, 10000)   → 5 个数
     ├─ _predict(...)                      → ("mode_A", "nominal", 0.65)
     └─ diagnose.auto_diagnose(...)        → 一句人话（每个类只调一次）
 └─ _render_waveform / _render_metrics / _render_diagnosis
```

注意这一行：`duration_sec=float(interval_sec)`（324 行）。**界面默认采集 3 秒，而训练时用的是 6 秒**——这就是"训练和推理不同分布"的第一处，比过零率那处更隐蔽：3 秒窗口下 FFT 分辨率从 1/6 Hz 变成 1/3 Hz，找峰、算抖动都会跟着变。

## 三、训练那一路（离线，跟推理并列）

`scopeai_pipeline.py` 不在推理链上，它负责生产那个 `.pkl`：

```
data/training_data.csv（未提交）
  + generate_synthetic_data()  80–191 行：每个类手写 (均值, 标准差)，再高斯采样
  → train_and_evaluate() 194–320 行：RF 200 棵树，5 折 CV，导出 .pkl
```

`generate_synthetic_data` 是整个仓库最该读的一段：Mode B/C 的 320 条样本**不是采出来的，是照着 `{"freq_hz": (5.0, 0.5), ...}` 这种表随机生成的**。每个类的中心是你（作者）自己填的，所以类与类天生分开，分类器当然 100%。

## 四、建议的阅读顺序

1. `features.py`（最短，纯函数，先建立"5 个数"的直觉）
2. `capture.py` 的 `_simulate_waveform`（24 行，看清"仿真"到底是什么）
3. `app.py` 的 `_run_sample_cycle`（20 行，看清调用顺序）
4. `diagnose.py` 的 `auto_diagnose`（40 行，看清"AI 到底拿到了什么"）
5. 最后再看 `pipeline.py` 的 `generate_synthetic_data`（理解 100% 从哪来）

`_capture_hardware` 和 Streamlit 的渲染函数可以整段跳过，它们是体力活。
